**La ingeniería de solicitudes**
Es el proceso de creación de instrucciones claras para guiar los sistemas de inteligencia artificial, como GitHub Copilot, para que pueda generar el código adecuado y que en cada contexto se adapte a las necesidades específicas del proyecto. Con esto garantiza que el código sea correcto sintáctica, funcional y contextualmente.  

**Principios de ingenieria de solicitudes**  
Existen las 4S como base para hacer solicitudes efectivas, que no tenía ni idea de esto:
* Single (única): centra la solicitud en una única tarea o pregunta bien definida.  
* Specific (específica): las instrucciones tienen que ser explícitas y detalladas.  
* Short (corta): Las solicitudes tienen que ser específicas, concisas y al grano. Con esto se garantiza la claridad sin sobrecargar Copilot ni complicar la interacción.
* Surround (enmarcada): usa nombres de archivo descriptivos y ten abiertos los archivos relacionados. Esto proporciona a Copilot un contexto enriquecido.  

**Aserción e iteración**  
Si el primer código que da no es lo que uno busca, es mejor no empezar de cero.  
Es mejor borrar el código sugerido editándolo, enriquecer el comentario con detalles y ejemplos agregados y volver a lanzar la pregunta (ósea, dandole al intro)

**Cadena de mensajes y administración del historial de chat**  
* Es mejor resumir el texto cuando las conversaciones se vuelven largas.  
* Restablecer y proporcionar contexto centrado para las nuevas características empezando con detalles esenciales.
* Usar referencias concisas al trabajo anterior en lugar de repetir las implementaciones.
* También es recomendable recomendar un rol, que actúe como un tipo especifico de experto, porque puede acelerar el desarrollo de lo que sea.  

**Flujo de proceso de solicitud de usuario**
1. Transmisión segura de solicitudes y recopilación de contexto.
El proceso empieza con la transmisión segura del mensaje que le escribimos a través de HTTPS, protegiendo la información confidencial. A la vez, recopila detalles de contexto como:
* El código anterior y posterior a la posición del cursor, para comprender el contexto inmediato del mensaje.
* El nombre y tipo del archivo que se está editando,  para adaptar las sugerencias de código al tipo de archivo específico.
* Información sobre las pestañas abiertas adyacentes, garantizando que el código generado se alinee con otros segmentos de código del mismo proyecto.
* Información sobre la estructura del proyecto y las rutas de acceso de los archivos
* Información sobre lenguajes y marcos de programación
* Preprocesamiento mediante la técnica Fill-in-the-Middle (FIM) para tener en cuenta tanto el contexto del código anterior como el siguiente, para comprenderlo todo mejor y ser más preciso.
2. Filtro de proxy.
Una vez recopilado el contexto y creada la solicitas, se pasa seguro a un servidor proxy. Este proxy filtra el tráfico bloqueando todo lo malo, tanto los intentos de piratear la solicitud como manipular el sistema para revelar detalles por ejemplo
3. Filtrado de toxicidad. 
Tiene un filtrado base para que no se promueva:
* Discursos de odio y contenido inapropiado: Copilot emplea algoritmos para detectar y prevenir la ingesta de discursos de odio, lenguaje ofensivo o contenido inapropiado.
* Datos personales: Copilot filtra activamente los datos personales, como nombres, direcciones o números de identificación, para proteger la privacidad del usuario y la seguridad de los datos.
4. Generación de código con LLM
Generan sugerencias de código adecuadas basándose en la comprensión de la solicitud y el contexto, garantizando que el código generado sea relevante, funcional y ajustado a los requisitos que se quiera en el proyecto.
5. Procesamiento posterior y validación de respuestas  
Habiendo hecho todo lo anterior,  se acaba comprobando la **calidad del código** y el **código público coincidente** aunque esto último es opcional, porque los administradores pueden habilitar que la ia devuelva sugerencias de +150 caracteres si se parece mucho al código público en Github, y si no supera estas comprobaciones, se suele descartar.
6. Entrega de sugerencias e inicio del bucle de retroalimentación.  
La ia inicia un bucle de retroalimentación basado en sus acciones para ampliar sus conocimientos y aprender y mejorar gracias a las modificaciones y rechazos de las sugerencias.
7. Repetición para solicitudes posteriores
El proceso se repite y se controla las solicitudes de usuario, entendiendo la intención y generando código en respuesta.  

**Datos de Github Copilot**
* Para sugerencias de código
No conserva ningúna solicitud como código u otro contexto y descarta las solicitudes cuando se devuelve una sugerencias. También se puede optar por no compartir las solicitudes con GitHub.
* Para el chat de GitHub Copilot.
Funciona como plataforma interactiva, llevando a cabo estos pasos:
* Formato, formateando la respuesta generada para una buena presentación en la interfaz del chat
* Interacción del usuario, interactúa con la respuesta y teniendo un historial de chats para facilitar la comprensión posterior.
* Retención de datos durante 28 días.
Todo esto también se aplica con el CLI, móvil y el chat de GitHub Copilot en GitHub.com.  

**Tipos de aviso**
Lo que admite por el chat, serían preguntas directas, solicitudes relacionadas con el código, consultas abiertas y solicitudes contextuales.  

Un LLM es un Modelo de Lenguaje Grande que se entrena para comprender generar y manipular el lenguaje humano. Tiene aspectos como la exposición de grandes volúmenes de datos, la descripción contextual relevante y coherente para que lo comprenda mejor, la integración del aprendizaje automático para producir textos eficaces, su versatilidad porque se adapta a muchos idiomas y dominios.
También se puede hacer un proceso que es, el ajuste. Con esto se entrena el modelo en un conjunto de datos mas pequeñito y especifico de tareas mientras se usan los conocimientos de un conjunto de datos más grande.  

Copilot usa otra optimización mejor, que es LoRA, agregando partes entrenables más peques a cada capa del modelo entrenado previamente en lugar de cambiar todo, ahorrando tiempo y recursos.
